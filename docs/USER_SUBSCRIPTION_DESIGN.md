# 多用户与双层订阅功能设计

本文记录 2.x 后续多用户/订阅模块的确定需求与安全边界。此设计文档不是已部署功能声明。

## 已确认需求

- 支持多个用户；每个用户有独立名称、UUID 集合和订阅令牌。
- 每个用户可分配七种入站中的任意子集。
- 每个用户拥有独立订阅，只返回分配给该用户的节点。
- 管理员另有总订阅，包含所有已启用用户的节点；管理员总订阅必须使用独立令牌。
- 用户禁用或删除后，撤销其订阅令牌，并从所有对应 Xray 入站中移除其 UUID。
- 不依赖第三方订阅转换网站；订阅生成、用户数据和令牌均由 VPS 本机管理。

## 目标架构

### 数据存储

建议使用独立文件 `/etc/xray-dual-protocol/users.json`，属主 root、权限 0600。每个用户记录至少包含：

- 稳定用户 ID、显示名称、启用状态、创建时间。
- 用户订阅令牌的哈希值（不保存可直接重放的明文令牌）。
- 被分配的入站 tag 列表。
- 按入站 tag 分配的 UUID。

管理员总订阅令牌单独保存并仅由 root 管理。令牌使用密码学安全随机数生成；创建时只展示一次，支持轮换和撤销。

### Xray 配置同步

- 为每个用户在被分配的入站中创建独立 UUID。
- 对 TCP + TLS/REALITY + Vision 等入站，新增客户端时必须保留该入站原有 flow 语义；非 Vision 入站不得错误添加 flow。
- 增删用户必须采用事务：先生成候选配置、验证 JSON、以 Xray 服务账户执行配置测试，再原子替换并重启；失败时恢复配置和用户数据库。
- 不能覆盖当前已有的七个默认 UUID。升级时将现有 UUID 迁移为一个名为“原有默认账号”的用户，保证现有客户端链接继续可用。
- 用户禁用/删除时只移除该用户 UUID，不影响其他用户或其他入站。

### 订阅服务

- 订阅服务只监听 `127.0.0.1`，不直接暴露公网监听端口。
- 由现有 Nginx TLS 站点反向代理到本机订阅服务；订阅路由使用高熵随机令牌。
- 用户订阅只输出该用户获分配的节点；管理员总订阅按明确策略汇总启用用户节点，去重并限制输出。
- 订阅响应不包含私钥、用户数据库、其他用户令牌或管理接口。
- 不提供公网 Web 管理后台；用户增删、分配和令牌轮换仅通过 root SSH 菜单执行。
- Nginx access log 对订阅路径必须脱敏或关闭该 location 的访问日志，避免令牌落盘。
- 禁止第三方转换服务；客户端可直接导入自建订阅 URL。若客户端需要特定订阅格式，服务端提供原生格式转换，不把链接发送给外部网站。

### 管理菜单

拟新增“用户与订阅管理”菜单：

1. 列出用户（仅显示名称、状态、分配节点数量，不显示完整令牌）。
2. 新建用户（输入名称、选择节点；UUID 和订阅令牌自动生成）。
3. 修改用户节点分配。
4. 启用/停用用户。
5. 删除用户（明确二次确认，撤销 UUID 和订阅令牌）。
6. 显示/轮换单用户订阅令牌。
7. 显示/轮换管理员总订阅令牌。
8. 复制/输出订阅地址。
9. 订阅服务状态与本机健康检查。

## 安全与隐私要求

- 订阅令牌至少 256 bit 随机熵；日志、错误信息和终端汇总不得打印完整令牌。
- 用户文件、令牌哈希、备份和订阅服务配置仅 root 可读；备份继续包含用户数据库且必须 0600。
- 订阅 URL 作为凭据处理；支持立即撤销和轮换。
- 订阅服务仅返回节点配置，不收集访问者 IP 以外的行为数据；默认不记录请求路径中的令牌。
- 管理操作前自动备份；失败时回滚 Xray 配置、用户数据库及 Nginx 路由。
- 迁移前检查现有配置、备份并提供 dry-run；不得未经确认覆盖已有客户端 UUID。

## 分阶段验收

1. 用户数据库格式、迁移和备份恢复测试。
2. 七种入站的多 UUID 配置测试，逐项确认 flow、path、SNI、REALITY 公钥和 TLS 参数不变。
3. 用户增删、停用、重新分配的事务故障注入测试。
4. 订阅服务仅绑定 localhost；Nginx TLS 代理和 access log 脱敏测试。
5. 用户订阅隔离测试：用户 A 不得看到用户 B 的 UUID/节点。
6. 管理员总订阅测试：只包含启用用户，且不暴露任何私钥或令牌。
7. V2RayN 实机导入测试、令牌撤销测试和 VPS 重启后自启动测试。

在上述验收完成前，不应把多用户订阅标记为可用，也不应将订阅 URL 投入日常使用。
